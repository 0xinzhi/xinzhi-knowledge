# XinZhiKnowledge · 知识机器（独立版）

一个独立的 [Slimefun](https://github.com/Slimefun/Slimefun4) 附属：把「知识之书」那套
「照着别的机器的配方反复刷产物」的能力，拆成**可放置的机器**。

> 本项目是从大一统附属 XinZhiTech 里摘出来的独立版本，单独维护配方抽取与批量合成的逻辑。
> 只依赖原版 + Slimefun 本体，**不点名任何其他附属**，装不装别的附属都能跑。

## 它做什么

四台机器 + 一件查询道具：

| 机器 | 作用 | 界面形态 |
|---|---|---|
| **知识合成机 · 输出优先** | 照识别到的机器跑「要扣料」的配方，产物区大（6 列） | 输入 2 列 / 输出 6 列 |
| **知识合成机 · 输入优先** | 同上，输入区大（6 列），适合一次塞很多原料 | 输入 6 列 / 输出 2 列 |
| **知识生成器** | 只跑「不消耗输入」的配方（卡片机、种植机这类），模板区认配方 | 输出 45 格 + 模板区 |
| **知识发电机** | 把一堆发电机收进一台，照它们的发电量往外送电 | 左燃料 / 右发电机 |
| **配方读取器**（道具） | 右键打开「某台机器的配方列表」，只读查询 | — |

## 怎么用

### 知识合成机

1. 把**要照着跑的那台机器**（粘液物品本体）放进**识别槽** —— 机器会去读它的配方；
2. 把原料放进输入区，产物会进输出区；
3. 机器列其它格子放**同款机器**可以叠台数（N 台 = 效率 ×N）；
4. 点**配方眼**可以锁定某一条配方（再点「取消选择」回到自动识别）。

槽位：

| | 识别槽 | 配方眼 | 状态卡 | 叠台数 | 输入 | 输出 |
|---|---|---|---|---|---|---|
| 输出优先 | 20 | 29 | 2 | 11 / 38 / 47 | 第 1–2 列（12 格） | 第 4–9 列（36 格） |
| 输入优先 | 24 | 33 | 6 | 15 / 42 / 51 | 第 1–6 列（36 格） | 第 8–9 列（12 格） |

### 知识生成器

- 识别槽放机器，**模板区（48 格）** 放「认配方用的那件东西」（卡片、种子、处理器…）；
- 模板对不上就不跑（模板是选择器，不是白送的原料）；
- 50–53 格放同款机器叠台数。

### 知识发电机

- 左边 4 列放**燃料**（只有需要烧燃料的发电机才要）；
- 右边 4 列放**发电机**本体，第一格 5 用来识别，其余叠台数；
- 中列 13 格显示「每 tick 发出 / 台数 / 本机存电 / 虚拟电量」；
- 22 格是**过载输出**：把缓冲 + 虚拟电量一次性灌进电力网络（可超容量），60 秒后强制归零。

## 效率与耗电

- **效率 = 机器台数 × 基准效率 ÷ 配方耗时**（千分之一累加，余数不丢）；
  配方 2 tick、4 台 ⇒ 每 tick 完成 2 次；配方 20 tick、2 台 ⇒ 10 tick 一次。
- **耗电**读的是被识别机器自己的耗电（J/tick × 配方 tick）；读不到就按
  `machine.energy-per-tick-when-unknown` 兜底，并在状态卡上标「能耗未知」。
- 产物槽**只要还有一格空着**就继续跑，全满才停。

## 配方从哪来

只认**精确配方**，展示配方（`getDisplayRecipes`）一律不采信 —— 展示配方经常只是摆设，
配方本身不完整。抽取顺序：

1. `AContainer#getMachineRecipes`
2. 实例字段（`recipes` / `machineRecipes` / `recipeList` / `templates[].recipes`）
3. `getRecipes()`
4. 配方载体（字段类型上带 `getRecipes()`，如 yml 驱动附属的 ticker）
5. 静态配方集合、矿机 / 种植机 / 材料机专用抽取

概率、加权抽取、抽组、模板这几类配方会被包装成对应类型（每次按原概率出货，不会「一次全给」）。

## 环境要求

| 项 | 版本 |
|---|---|
| 服务端 | Paper / Spigot 1.21+（`api-version: 1.21`） |
| Slimefun | Slimefun4（2025.x） |
| JDK | 21 |

## 构建

```bash
mvn clean package
# 产物：target/xinzhi-knowledge-1.0.0.jar
```

把 jar 丢进 `plugins/` 与 Slimefun 一起启动。首次启动生成 `plugins/XinZhiKnowledge/config.yml`。

## 指令

| 指令 | 作用 |
|---|---|
| `/xzk info` | 版本、构建时间、每台机器的平均 tick 耗时 |
| `/xzk reload` | 重载配置并清空配方缓存（需要 `xzk.admin`） |
| `/xzk scan <机器id>` | 打印「这台机器扫出了多少条配方 / 多少条不消耗输入 / 耗电」 |
| `/xzk dump <机器id>` | 打印配方对象与全部字段（排障用） |

## 权限

| 权限 | 说明 |
|---|---|
| `xzk.use` | 使用机器（默认所有人） |
| `xzk.admin` | `/xzk reload` 等管理指令 |
